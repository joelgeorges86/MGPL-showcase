## Deviations and choices made by the operator agent

- Restore containers ran with `--user 1000:1000` so restored files match the app's uid (the originals were owned by 1000). The deployed sidecar runs as root (image default). A restore run as root was not tested.
- Integrity checks and counts ran against a **copy** in a throwaway container from the app image (`better-sqlite3`). The host has no `sqlite3`. The baseline used `docker exec` into the running app, read-only.
- Containers were stopped and started with `docker stop` / `docker start`, not compose. Nothing was recreated.

## Observations

1. B2 `B2_ENDPOINT` is a bare hostname (no scheme). On litestream v0.3.14 the snapshot, WAL upload, listing and restore all succeeded against it.
2. `litestream restore` leaves `<db>.tmp-shm` and a 0-byte `<db>.tmp-wal` next to the database. Restored `.db` mode is 0600; the originals were 0644.
3. `mgpl-preprod-app` did not exit on SIGTERM: `Exited (137)` after Docker's 10 s timeout.
4. `mgpl-preprod-litestream` carries compose project label `mgpl`; `mgpl-preprod-app` carries `mgpl-preprod`. The sidecar was brought up under a different project name than the documented `-p mgpl-preprod`.
5. `AuthUsers` = 1 in the baseline. The drill brief said every user-content table was 0 rows as of 14:24:56Z. That was inaccurate: the 14:24:56Z counts (`G3-restore-drill-scope-enumeration-2026-09-23T1413Z.md` §4) already show `AuthUsers` = 1. The row predates the brief, so the drill didn't find a new discrepancy. It was restored intact from both replicas.
6. On start, the app logged `Missing tables detected (will be created by DDL): AppReviews, AppCompletionRoadmap` and created them, so the live DB now differs from the restored bytes (954368 vs 913408 bytes). This is expected app behaviour and not a restore defect.
7. Before the drill, R2 had logged no writes since the 20:05 sidecar start. The replica `lag` column (49m24s) was time since the last upload, not a data gap: R2 already held the DB content from the 19:15 run, and the restore proved it byte-identical.
