## 5. Findings

### F-01 — General DeepSeek API spending is not authorized

- **Location:** `AGENTS.md` §3.1 (as summarized); proposal §4.E.
- **Severity:** **Critical.**
- **Evidence disposition:** Operator-reported; source not inspected.
- **Description:** The existing ledger entries are described as narrowly bounded to named Vertex/Gemini routes. They do not authorize a general Cline/DeepSeek engineering route. The proposal treats DeepSeek as “available” and “selectively” used without a defined ceiling, stop condition, or expiry.
- **Why it matters:** An unauthorized billable route is a direct spending-control violation. “Low cost” is not an authorization. A route that is cheap per token can still accumulate cost through retries, long contexts, and failed attempts.
- **Exact correction:** Before any Cline/DeepSeek use, add a bounded ledger entry specifying: named route (Cline → DeepSeek provider), permitted models, task classes, request cap, dollar cap, stop condition, expiry date, and operator approval record. If those are not established, keep the route inactive.
- **Blocks adoption:** **Yes.**

### F-02 — Claude Desktop’s auditor slot does not authorize ordinary review of ChatGPT-authored documents

- **Location:** PACE Document Auditor row; proposal §4.B.
- **Severity:** **Critical.**
- **Evidence disposition:** Operator-reported; source not inspected.
- **Description:** The current Claude Desktop Alternate slot is described as restricted to non-Claude-authored and non-OpenAI-authored documents. A ChatGPT-authored WUD is OpenAI-authored. Claude’s review is therefore advisory unless the operator records a scoped exception or amends the restriction.
- **Why it matters:** An advisory review is not an operative audit. Treating it as operative would bypass the author/auditor vendor-separation rule without a recorded decision. Conversely, refusing any Claude review would leave the ordinary workflow without a practical document auditor, because the Primary slot is recused.
- **Exact correction:** The operator should record a **scoped temporary auditor exception** for Claude Desktop to audit ChatGPT-authored documents for the trial, preserving the general different-vendor rule outside the exception. Separately, amend the anomalous Claude restriction in the PACE matrix prospectively. The exception should be recorded **separately from approval of the change request** because it changes an assignment restriction, not just the proposal’s content.
- **Blocks adoption:** **Yes.**

### F-03 — The transition PR cannot be reviewed by the agent placing it

- **Location:** `AGENTS.md` §5; `DOCS/CODE_REVIEW_WORKFLOW.md`; proposal §4.C.
- **Severity:** **Critical.**
- **Evidence disposition:** Operator-reported; source not inspected.
- **Description:** The proposal would make Claude Code the ordinary PR reviewer. The governance-transition PR would implement that change. If Claude Code is also the placement agent, it would be reviewing or effectively certifying its own placement work. The current Codex requirement remains binding until the amendment is adopted; the amendment cannot self-authorize its own review waiver.
- **Why it matters:** This is the central self-certification risk in the proposal. A governance change that removes the reviewer who would otherwise review it is procedurally invalid unless an independent reviewer performs the transition review.
- **Exact correction:** The transition PR must be reviewed under the **current** Codex requirement, or by another independent reviewer who did not author or place the content, with the review identifying the reviewed commit. Claude Code may place the amendment but must not review its own placement. The new Claude Code PR-review rule becomes effective only after operator merge and a recorded effective date.
- **Blocks adoption:** **Yes.**

### F-04 — PACE matrix does not demonstrate four independent backup levels

- **Location:** PACE matrix; independence rules on shared harnesses/vendors/accounts/hosts.
- **Severity:** **High.**
- **Evidence disposition:** Operator-reported; matrix not inspected.
- **Description:** The proposed model concentrates document review and PR review on Anthropic (Claude Desktop and Claude Code) and authoring plus possible implementation on OpenAI (ChatGPT and Codex). Antigravity provides Google diversity, but only for implementation. DeepSeek provides another vendor only for implementation. The matrix may have four labels but not four independent upstream vendors for each role.
- **Why it matters:** PACE levels are resilience claims. If Alternate and Contingency share the same upstream vendor, they are not independent backup levels for a vendor-level outage or policy change. Treating them as four levels would be inaccurate.
- **Exact correction:** Record actual independence per role. Where only two independent upstream vendors exist, state that explicitly and identify the concentration. Do not invent a fourth vendor. Mitigations can include sequencing rather than parallel capacity.
- **Blocks adoption:** **Yes**, as a recording and accuracy correction, not necessarily as a rejection of the roles themselves.

### F-05 — Antigravity/Gemini eligibility is overbroad and conflates models

- **Location:** Proposal §4.D; historical Gemini assessment files.
- **Severity:** **High.**
- **Evidence disposition:** Operator-reported; historical reports not inspected.
- **Description:** The historical failures are reported for Gemini 3.1 Pro on chatbot and Gemini 2.5 Pro via Cline/Vertex. Those failures are relevant but not universal. The proposal nonetheless grants broad Antigravity engineering eligibility for Gemini 3.8 Flash and Gemini 4 Argon. No binding qualification for either model/task combination is described.
- **Why it matters:** A model change is not automatically a new qualification. Successful 3.8 Flash use would not establish 4 Argon reliability. Broad eligibility before qualification creates a quality and governance gap, especially for complex work.
- **Exact correction:** Grant **explicit model/task qualifications**: e.g., “Gemini 3.8 Flash — routine development, tests, repository discovery, gate diagnosis,” and separately “Gemini 4 Argon — complex engineering only when explicitly selected and after a bounded qualification.” Preserve the historical failures unchanged, without erasing or universalizing them.
- **Blocks adoption:** **Yes**, until the qualification record exists.

### F-06 — ChatGPT’s issue-determination role must not become filing authority

- **Location:** `AGENTS.md` §10.1; proposal §4.A.
- **Severity:** **High.**
- **Evidence disposition:** Operator-reported; source not inspected.
- **Description:** The proposal says ChatGPT “determines, where appropriate, whether new GitHub issues or updates should be proposed.” That is compatible with drafting and proposing. It is not compatible with self-filing under §10.1, which requires separation between issue-body author and filing agent, a staged file named by the operator, SHA-256 evidence, no alteration, and duplicate search.
- **Why it matters:** Issue creation is a reserved/propose-approve-execute action. Letting the author determine and file would collapse the separation §10.1 exists to preserve.
- **Exact correction:** Clarify in the amendment that ChatGPT may draft/propose issue content, but filing remains with an authorized filing agent under §10.1 and operator approval. Copilot may file only after those conditions are met.
- **Blocks adoption:** **Yes**, as a clarification.

### F-07 — OpenAI auto-reload is an uncontrolled spending authority

- **Location:** Reserved Actions model; billing settings.
- **Severity:** **High.**
- **Evidence disposition:** Operator-reported; billing settings not independently verified.
- **Description:** The operator reportedly has auto-reload enabled without a clearly established ceiling. If the monthly reload limit is blank or absent, auto-reload can purchase repeatedly. This is a recurring spending authorization, not a one-time purchase.
- **Why it matters:** The proposal’s cost-control goal is undermined if an OpenAI billing route can replenish without a recorded cap. A spending cap is not satisfied by “the operator is watching.”
- **Exact correction:** Record a monthly reload limit or disable auto-reload pending operator decision. Treat enabling or raising the limit as a Reserved Action. Separately, verify whether the observed “short reset” is an AI-credit reset or a different billing-cycle artifact; do not assume it is the monthly subscription allowance reset.
- **Blocks adoption:** **Yes**, until a cap or disable decision is recorded.

### F-08 — Mandatory Claude Desktop + Claude Code review may bottleneck one Anthropic allowance

- **Location:** Proposal §4.B and §4.C; subscription/allowance facts.
- **Severity:** **Medium** (operational risk, not a formal rule violation).
- **Evidence disposition:** Inferred from the proposal’s role assignments; actual allowance balances unknown.
- **Description:** Both the ordinary document review and the ordinary PR review would consume Anthropic capacity. If they share a subscription or rate-limit pool, a busy week could exhaust the allowance at the review stage, which is precisely when throughput matters.
- **Why it matters:** The proposal aims to prevent allowance exhaustion but may relocate it to the review bottleneck.
- **Exact correction:** Record whether Claude Desktop and Claude Code share an allowance or account. If they do, define a fallback ordering (e.g., Codex for PR review where independence permits; Claude Desktop for document review; or DeepSeek for first-pass advisory review) without weakening formal independence. Monitor review-queue delay as a trial metric.
- **Blocks adoption:** No, provided the bottleneck is acknowledged and a fallback is recorded.

### F-09 — GitHub Copilot reset observation appears inconsistent with documented billing

- **Location:** Proposal §4.G.
- **Severity:** **Low.**
- **Evidence disposition:** Sourced externally; the operator’s specific observation is operator-reported.
- **Description:** Public GitHub documentation and community reports indicate Copilot AI Credits reset monthly on the 1st at 00:00 UTC, not on a short interval. The operator’s “short usage-reset interval” may be a different mechanism (e.g., premium-request recovery, session limit, or plan-specific behavior).
- **Why it matters:** Cost planning based on an incorrect reset assumption can misallocate work.
- **Exact correction:** Verify the specific Copilot plan’s billing mechanism before relying on any reset interval. Do not equate it with the ChatGPT subscription’s monthly reset. Restricting Copilot to small tasks is sensible, but deterministic commands should be the default where they accomplish the same result.
- **Blocks adoption:** No.

## 7. Financial and quota analysis

**Confirmed external pricing facts (not MGPL-specific balances):**

- DeepSeek V4 Flash is extremely inexpensive at published API rates — on the order of $0.14 per million input tokens and $0.28 per million output tokens, with much lower cached-input rates. Cline’s routing can inflate effective costs if provider pinning is absent; one public issue reports 3–5× inflation from unpinned OpenRouter routing.

- OpenAI auto-reload supports an optional monthly reload limit. Leaving the limit blank permits unlimited automatic recharges. This is a confirmed product behavior, not an MGPL-specific finding.

**Operations consuming capacity or expenditure:**

| Operation | Likely cost mechanism | Bottleneck risk |
|---|---|---|
| ChatGPT authoring/research | ChatGPT subscription allowance, possibly purchased credits/auto-reload | Auto-reload without cap; weekly allowance exhaustion |

**Qualitative economic assessment.** DeepSeek is likely the lowest marginal-cost implementation route, but token price is not total cost. The more serious financial risk is **not** DeepSeek; it is **uncontrolled auto-reload and shared Anthropic review capacity**. A cheap implementer does not help if the review stage is the bottleneck or if an OpenAI billing route replenishes without a ceiling.

**No invented caps.** I do not assert a dollar ceiling. The operator must record actual balances and caps; the audit can only specify the structure those controls must take.

I do **not** recommend rejecting the model outright. I do **not** recommend adopting as proposed.
